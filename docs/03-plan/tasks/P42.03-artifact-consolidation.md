## Description

Three independent contributors to file noise, all cheap to fix:

1. `/mae-req` and `/mae-design` each save **twice** per invocation — a draft in step 3 and a report in step 5. Merging them halves the file count for those commands with no behavior change.
2. `/md` has one mode today. It needs two: save the previous response, or force the current one to a file.
3. The agent routinely writes a file **and** repeats its full content in chat, doubling token cost and burying the link. MAESTRO.md already forbids this once, in § Output Standard, where it is not read at the moment it matters.

## Acceptance Criteria

- [ ] `/mae-req` produces **one** artifact per invocation — the requirements draft, with a short report header (Summary / Flags / Next Steps) rather than a separate report file
- [ ] `/mae-design` likewise
- [ ] `/md` alone, after a response → saves the **previous** response verbatim to a numbered session file
- [ ] `/md` inside a query → forces **this** response to be written to file(s), overriding `response_capture`
- [ ] Both `/md` modes documented in `.maestro/commands/md.md` with examples
- [ ] Global rule restated in each command's output section: **when output goes to a file, chat gets a link and one sentence — never a duplicate of the file**
- [ ] The same rule added to the definition-of-done checklist (M04.13) so it is verifiable rather than aspirational

## Files

- `.maestro/commands/mae-req.md` — merge steps 3 and 5
- `.maestro/commands/mae-design.md` — merge steps 3 and 5
- `.maestro/commands/md.md` — two-mode semantics
- `.maestro/commands/*.md` — output rule restated where each command reports
- `MAESTRO.md` — § Artifact Capture: `/md` semantics; no-duplication rule promoted from a single mention to a stated invariant

## Notes

The no-duplication rule is violated constantly, including by the agent that wrote this task file. Stating it once in a general section demonstrably does not work — it needs to sit next to each command's output step, which is where the decision actually gets made.

Merging draft+report is safe because the draft is the artifact; the report was always a wrapper around it. Keep the report *header* (Summary, Flags, Next Steps) — that content is useful; the separate file was not.
