## Description

Two external developers independently rejected Maestro for creating a file per response. The cause is a rule that saves **transcripts** rather than **work products**: *"save substantive responses unless very short (< 80 words)."* Word count was always a proxy for "is this an artifact," and it is the wrong proxy — a 400-word comparison of two libraries is not an artifact; a 60-word decision record is.

Replace the rule, then make the remaining volume configurable. OpenSpec's model (files only for typed artifacts) is the reference point; three tiers cover the range between it and current behavior.

## Acceptance Criteria

- [x] The word-count rule is **removed** from MAESTRO.md and from the CLAUDE.md template, replaced with: *"A file is written when the output is a work product — something a later session, another person, or a client would read on its own. Not when it is long."*
- [x] Artifact defined explicitly per command, in each command file: explore → report + questions file; req → requirements draft; design → design draft; plan → ROADMAP + task files; poc → POC.md + report; do → implementation report when substantial; review → findings report
- [x] `response_capture` documented with three values: `"all"` | `"artifacts"` (default) | `"minimal"`
- [x] `"artifacts"`: command artifacts always saved; conversational answers stay in chat
- [x] `"minimal"`: only canonical promotions to `docs/` and explore reports; command reports stay in chat unless asked
- [x] `"all"`: current behavior preserved for audit-heavy users
- [x] Absent key = documented default (`"artifacts"`), so upgraded projects without the key behave predictably; the installer appends the missing key (P42.08c)
- [x] Setting readable from `maestro.local.toml` (personal preference — no restrict-only limit here, unlike git)
- [x] `install.sh` asks: "Save every response, or only work products?" → writes the answer
- [x] Install output mentions `/md` as the save-on-demand escape hatch, so a `"minimal"` user knows how to keep something

## Notes

Three values rather than two because the two critics are not in the same place — one wants fewer files, one wants nearly none. A blunt `files | chat` toggle would ship a mode that silently loses explore reports and drafts, i.e. a mode that breaks the product.

Note the irony worth avoiding: this repo's own sessions demonstrate the failure mode the rule creates. Fixing the rule is more valuable than any setting.
