## Acceptance Criteria

- [x] `/mae-scope "{description}"` and `/mae-scope path/to/request.md` both accepted; with no argument, reads new files in `docs/00-reference/` and asks which one
- [x] **Step 1 Intake:** reads the request plus REQUIREMENTS.md, DESIGN.md, ROADMAP.md, and task index (titles only). Decomposes the request into discrete capabilities — a "small request" is usually three
- [x] **Step 2 Classify** each capability as *additive* (touches nothing existing), *modifying* (changes settled behavior), or *conflicting* (contradicts a shipped requirement or a recorded decision). Conflicts are listed with the exact requirement/decision they contradict
- [x] **Size check:** if the change adds a whole product area rather than a milestone (heuristic: > 5 capabilities, or capabilities with no anchor in existing DESIGN.md sections), say so and recommend `/mae-explore {area}` first instead of proceeding
- [x] **Step 3 Impact analysis** → `.sessions/{NNN}/NN_scope-delta.md` using `## Requirements / ## Design / ## Roadmap / ## Decisions needed` sections and `ADDED / MODIFIED / REMOVED / CONFLICT` line prefixes (the vocabulary of D19). This file is client-sendable: it answers "what does this cost" before any code
- [x] Step 3 is **analysis only** — no canonical file is touched
- [x] **Step 4 Apply, on explicit confirmation:** writes deltas into REQUIREMENTS.md and DESIGN.md (review-required diffs), adds a milestone to ROADMAP.md, generates task files, and appends a decision row for every CONFLICT that was resolved
- [x] **Partial approval:** the user may approve a subset of capabilities. Approved ones apply; the rest are recorded under a `## Deferred scope` section in HANDOFF.md with the date — they must not silently evaporate
- [x] Alias `msc` added alongside the other 3-letter aliases
- [x] Added to `install.sh`, `.claude/commands/`, MAESTRO.md command table, and `/mae-help` (suggested when `docs/00-reference/` has files newer than REQUIREMENTS.md)
