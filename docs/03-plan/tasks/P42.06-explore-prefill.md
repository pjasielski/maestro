## Description

A question the user only has to confirm costs seconds; a blank one costs minutes. Where the agent has a defensible answer it should fill it in — but never where a wrong guess is expensive, and never where only the user or client holds the knowledge.

Was M04.14, and before that was earmarked as a v0.4.1 patch in session 018 that never shipped. Full rationale and a longer draft in `018-reconciliation.md/05-skills-forensics-and-next-steps.md` §3. **Shorten that draft** — it was written as prose and is too long for a command file. Target the table plus four bullets.

## Acceptance Criteria

- [ ] Rule added to `.maestro/commands/mae-explore.md` under Questions Format, **condensed** to a table plus ≤ 4 bullets
- [ ] The test is **consequence-based, not confidence-based**: what does a wrong guess cost?

  - Changes a value or scope, build still valid → pre-fill as a stated assumption
  - Wrong means wasted work or a silently wrong output → leave open

## Notes

The trap the rule exists to prevent: **a confident pre-fill on a question only the client can answer reads as an answer and gets silently accepted.** That is worse than not asking, because it launders a guess into a decision.

The `(assumed)` middle marker is what makes it safe — without it, judgement calls get filed as derived facts and stop being reviewed.
