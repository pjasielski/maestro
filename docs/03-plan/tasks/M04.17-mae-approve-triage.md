## Description

The user annotates generated artifacts inline — approving some parts, rejecting others, commenting on the rest — and the agent's interpretation of those annotations is invisible until it has already acted. The cheapest fix is to make the interpretation visible *first*: read the file, show a triage table, wait.

This is the **triage-only** version. The approval stamp that prevents `/mae-req` and `/mae-design` from regenerating an approved section is M05.10 and is not built here.

## Acceptance Criteria

- [ ] `/mae-approve {file}` reads the file and extracts every inline annotation: blockquote comments (`> …`), inline backtick comments (`` `…` `` on their own line after a paragraph), and HTML comments
- [ ] Recognized prefixes: `OK` (approved), `NO` (rejected), `?` (needs discussion), `CHANGE:` (approved with modification). Unprefixed comments are interpreted and **marked as interpreted** in the table
- [ ] Output: a triage table — annotation excerpt · location (heading) · bucket · agent's reading — shown in chat, then **wait for confirmation** before acting
- [ ] On confirmation: approved/modified content is promoted to `docs/` per the existing promotion flow; rejected sections are struck from the promoted copy; `?` items are appended to the session `_summary.md` open questions
- [ ] Clean file with no annotations = approve wholesale and promote (the fast path)
- [ ] Description states the contrast with `/mae-review` explicitly: review is agent → user (quality findings); approve is user → agent (verdict processing). Both command files carry the sentence so future skill triggers do not fight
