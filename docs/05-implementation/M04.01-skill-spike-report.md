### Findings

**F1. Frontmatter fields needed.** Spec fields only: `name`, `description` (required), `license`, `compatibility`, `metadata` (optional). The reference validator (`uvx --from skills-ref agentskills validate`) passes the skill, and passes it through the symlink. Tier is carried in `metadata.maestro-tier`, which is spec-safe. String-only metadata values, so version numbers are quoted.

**F2. The validator rejects every tool-specific field.** `disable-model-invocation` (Claude Code, Cursor), `when_to_use` and `paths` (Claude Code) all fail with "Unexpected fields in frontmatter". There is no spec-level way to say "user-only". Consequence for the explicit tier (do, sync, init): either accept one validator warning per explicit skill, or enforce it in the body. Convention decision recorded in M04.02.

**F3. Placement.** Claude Code reads `.claude/skills/`. Cursor reads `.agents/skills/` and `.cursor/skills/`, plus `.claude/skills/` and `.codex/skills/` as legacy paths. Codex reads `.agents/skills/` (repo scope, walking up to repo root) and `~/.agents/skills`. So two symlinks cover three tools. Cursor will see the skill via two paths; whether it deduplicates is a test item. Codex disables implicit invocation through a sidecar `agents/openai.yaml` (`allow_implicit_invocation: false`), not frontmatter.

**F4. Supporting-file loading.** The spec loads `name` and `description` at startup (about 100 tokens), the body on activation (under 5,000 tokens recommended, under 500 lines), and referenced files only when read. Relative links from the skill root work unchanged through the symlink. The explore report template stays at `.maestro/templates/explore.md` and is referenced by project path, because it is shared with the installer; moving templates into skills is M04.03's call and would break `install.sh`'s template loop today.

**F5. Trigger phrasing.** Pattern used, from the agentskills.io description guidance plus the 015 draft: one clause on what it produces → "Use when …" listing user intents including ones that never say the keyword → the slash and alias names so typed invocations route here → "Do NOT use to …" naming the adjacent Maestro skill for every near-miss, so the model routes instead of declining. Description is 735 characters; the spec cap is 1,024, and Claude Code truncates at 1,536. Misfire risk is highest for "what should we ask the client" (should trigger) versus "answer this question about the codebase" (should not); the query set covers both.

**F6. Namespace collision.** Claude Code lists `.claude/commands/mae-explore.md` and `.claude/skills/mae-explore/` under the same `/mae-explore`. The docs say skills are preferred for new work and command files still work, but which one wins on a name clash is not documented. Test item 1 below.

**F7. Behavior preserved.** Session-numbered artifacts, `**Response:** _` placeholders, no question cap, readiness block in `_summary.md`, promotion prompt for `doc`. One addition: a fit check that applies only when the model invoked the skill itself, so an auto-trigger in a post-exploration project announces itself instead of silently writing a document.
